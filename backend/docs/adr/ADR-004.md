# ADR-004: Por que Domain puro?

## Status

Aceito

## Contexto

O domínio representa as regras do negócio e deve ser a fonte de verdade do sistema. Dependências de infraestrutura (GORM, HTTP, SQL) no domínio violariam este princípio e acoplariam as regras de negócio a detalhes técnicos.

## Decisão

Mantemos o domínio completamente puro:
- Sem tags GORM
- Sem tags SQL
- Sem dependência de infraestrutura
- Sem dependência de SQLite
- Sem dependência de HTTP
- Sem dependência de Repository

**Estrutura:**
- `internal/domain/*.go`: Domain models puros
- `internal/ports/*.go`: Interfaces de repository
- `internal/infra/repository/*.go`: Implementações com GORM
- Mappers convertem GORM models ↔ Domain models

## Consequências

### Positivas
- Regras de negócio independentes de tecnologia
- Fácil testabilidade do domínio
- Fácil mudar de tecnologia de persistência
- Conformidade com princípio #1 do 06-DOMINIO.md
- Evolução contínua facilitada

### Negativas
- Boilerplate adicional (mappers)
- Curva de aprendizado inicial
- Mais código para manter

## Alternativas Consideradas

1. **Tags GORM no domain:** Rejeitado - acopla domínio à infraestrutura
2. **Active Record:** Rejeitado - viola separação de responsabilidades
3. **Domain com dependência de repository:** Rejeitado - viola pureza do domínio
