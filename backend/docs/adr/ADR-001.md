# ADR-001: Por que utilizamos Snapshot?

## Status

Aceito

## Contexto

O sistema precisa manter o histórico de pedidos de forma imutável. Produtos e ingredientes podem ter seus dados alterados (nome, preço, descrição, unidade) ao longo do tempo, mas os pedidos antigos devem refletir exatamente o estado existente no momento da venda.

## Decisão

Utilizamos Snapshot para congelar os dados relevantes no momento da venda:

**Produto (OrderItem):**
- ProductName
- ProductDescription
- ProductIsComposto
- UnitPrice

**Ingrediente (StockAdjustmentPending):**
- IngredientName
- IngredientUnit

O Snapshot pertence ao Pedido/Ajuste, nunca ao Produto/Ingrediente.

## Consequências

### Positivas
- Histórico imutável garantido
- Pedidos não são afetados por alterações no cadastro
- Auditoria confiável
- Conformidade com princípio #4 do 06-DOMINIO.md

### Negativas
- Duplicação de dados (trade-off aceito)
- Aumento de armazenamento (trade-off aceito)
- Complexidade adicional na criação de pedidos

## Alternativas Consideradas

1. **Referenciar cadastro atual:** Rejeitado - viola imutabilidade do histórico
2. **Event Sourcing:** Rejeitado - complexidade desnecessária para MVP
3. **Versionamento de cadastro:** Rejeitado - complexidade desnecessária para MVP
